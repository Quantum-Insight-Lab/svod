# Храповик

Ограниченный цикл сборки, который растит проект **СВОД** по одной возможности
за раз: неподделываемая приёмка и обязательная остановка на человека между
ступенями. Только стандартная библиотека Python 3.10+; git — через `subprocess`.

## Части

- `svod.py` — ядро СВОД (R0): утверждения с провенансом, вычисляемая
  уверенность, обучение надёжности источников. Команды
  `seed / add / ingest / ask / learn / sources / top / history / tick`.
- `ratchet.py` — храповик (оркестратор + арбитр + бегунок по лестнице).
- `ladder.json` — лестница ступеней. **Редактирует только человек.** Храповик
  читает её и меняет лишь поле `status`; порядок и содержание не трогает.
- `journal.jsonl` — append-only журнал попыток (провенанс приёмки). Не входит
  в git (см. `.gitignore`): это внешний неизменяемый лог.

## Лестница

Упорядоченный список ступеней. Каждая ступень:

| поле       | смысл                                                              |
|------------|--------------------------------------------------------------------|
| `id`       | идентификатор ступени                                              |
| `title`    | человекочитаемое имя                                               |
| `intent`   | какую возможность добавляем                                        |
| `apply`    | команды, реализующие минимальное изменение (декларативный codegen) |
| `checks`   | команды приёмки — **это и есть тест ступени**                      |
| `approved` | `true`, только если человек разрешил старт ступени                 |
| `status`   | `pending` → `passed` → `shipped`                                   |

## Команды храповика

```bash
python ratchet.py tick            # один удар: максимум одна попытка одной ступени
python ratchet.py ship T1         # человек: пометить passed-ступень как shipped
python ratchet.py status          # состояние лестницы (read-only)
python ratchet.py verify T1       # заново прогнать checks и сверить с журналом
```

**Windows (PowerShell):** из текущей папки не `ratchet.py status`, а одно из:

```powershell
python ratchet.py status
.\ratchet.cmd status
```

## Один удар (`tick`)

Ровно один раз за вызов:

1. Привести дерево к чистому (снапшот-коммит, если грязное).
2. Прочитать `ladder.json`, взять первую ступень со `status != shipped`.
3. Если `approved = false` — напечатать «жду одобрения ступени X» и выйти (код 0).
   Если ступень уже `passed` — напечатать, что нужен `ship`, и выйти.
4. Иначе выполнить `apply` (минимальное изменение), затем `checks`.
5. **Зелено** (все коды возврата = 0): `git commit` «ratchet: ID passed»,
   дописать журнал, выставить `status = passed`, напечатать сводку и **СТОП**.
6. **Красно**: `git reset --hard` + `git clean` к последнему коммиту, дописать
   причину в журнал, напечатать сводку и **СТОП**.

За один tick — максимум одна попытка одной ступени. Цикла по ступеням нет.

## Изоляция приёмки

`apply` и `checks` исполняются с переменной окружения `SVOD_STATE`, указывающей
на отдельный временный файл `.accept_state.json`. Поэтому приёмка (в т.ч.
`svod.py seed` внутри `checks`) **никогда не перезаписывает рабочую базу**
`svod.json` — тесты гоняются на синтетике в изоляции, а живая база растёт сама.

- Ядро: `svod.py` читает `STATE_PATH` из `SVOD_STATE` (по умолчанию — `svod.json`).
- Храповик перед каждой фазой стирает `.accept_state.json` для свежего старта.
- `harvest.py` / `dedup.py` / проверки идут через API ядра, поэтому изоляцию
  подхватывают автоматически.

Наполнять рабочую базу по-настоящему: `python svod.py add ИСТОЧНИК ТЕМА УТВЕРЖДЕНИЕ`
или `python svod.py ingest ФАЙЛ` — это пишет в `svod.json`, не в приёмочный файл.

## Человеческий шлюз (собачка храповика)

Храповик **никогда** не переводит `passed → shipped` и не берёт следующую
ступень сам. Это делает человек:

- `python ratchet.py ship <id>` — помечает ступень `shipped`;
- выставляет `approved = true` у следующей ступени в `ladder.json`.

Нет ни одной ветви кода, которая продвигается по лестнице без человека.

## Гарантии

- **Песочница.** Все подпроцессы исполняются с `cwd` = каталог проекта; за его
  пределы храповик не выходит; сетевых вызовов в коде нет (сеть выключена).
- **Версионный контроль.** Перед изменением дерево чистое (иначе снапшот-коммит);
  любое изменение либо коммитится, либо откатывается; репозиторий не ломается.
  Личность коммитов передаётся инлайн (`-c user.name=...`), глобальный git
  config не трогается.
- **Ограниченность.** Цели «довести до канона» не существует — есть только
  конечная лестница; продвижение по одной ступени и только после человека.
- **Никакого самозачёта.** Вердикт выводится исключительно из кодов возврата и
  захваченного вывода `checks`, никогда из мнения агента.
- **Изоляция приёмки.** Тесты гоняются с `SVOD_STATE=.accept_state.json`;
  рабочий `svod.json` приёмкой не перезаписывается.

## Привязка к OpenClaw

`python ratchet.py tick` ставится на **сердцебиение/cron OpenClaw**: один удар
сердцебиения = один `tick`. Сводку, которую печатает `tick`, OpenClaw
доставляет человеку в чат. Человек отвечает одним из:

- одобрить следующую ступень (`approved = true` в `ladder.json`);
- отгрузить пройденную (`ratchet ship <id>`);
- запросить разбор/откат (откат красной попытки храповик уже делает сам).

Поскольку `tick` обрабатывает максимум одну ступень и останавливается на
человеческом шлюзе, автономный фон OpenClaw не может «убежать» вперёд по
лестнице: каждый зуб храповика фиксирует человек.
