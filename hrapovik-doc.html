Храповик

Автономная, но ограниченная сборка СВОДа на базе OpenClaw

версия 0.1статус: рабочий черновик владелец: команда СВОДобновлено: 29 мая 2026

В двух строках

Храповик растит СВОД по одной возможности за раз и никогда не крутится «до победного». Двигатель — сердцебиение OpenClaw. Топливо — лестница возможностей, которую задаёт человек. Тормоз — приёмка, которую агент не может подделать. Собачка храповика (то, что не даёт откатиться назад) — обязательный человеческий шлюз между ступенями.

Правило, которое нельзя нарушать: агент поднимается ровно на одну ступень и останавливается, пока человек не скажет «дальше».

§1 Зачем храповик, а не вечный двигатель

Автономные циклы сборки сегодня предсказуемо ломаются одинаково: они дрейфуют, переусложняют, ломают то, что работало, галлюцинируют, что тесты прошли, и ставят зачёт сами себе. Храповик существует, чтобы превратить «улучшайся вечно» в «поднимись на одну проверенную и полезную ступень — и остановись».

Ключевая ловушка — слово «канон». В нём слиплись два разных канона. Канон софта: СВОД дорос до нужного набора возможностей, тесты зелёные. Это конечная, достижимая цель. Канон знания: будто СВОД наконец собрал истинные факты о мире — а такого терминального состояния не существует (нет оракула истины; уверенность — не истина). Агенту дают только первый канон. Цель «довести знание до канона» в систему не закладывается никогда, иначе агенту некуда остановиться.

Метафора буквальна: храповик крутится только вперёд, потому что собачка блокирует обратный ход. Здесь собачка — человеческий шлюз, а зубья — отгруженные, проверенные ступени, которые больше не пересматривают.

§2 Архитектура

Пять частей, каждая с одной обязанностью:

  • Двигатель — сердцебиение OpenClaw. OpenClaw — это автономный локальный агент, который работает в фоне и на регулярном интервале сам решает, действовать или ждать, поднимая человека только при необходимости. Один «удар» = один запуск храповика.
  • Что растим — СВОД. Существующий svod.py: утверждения с провенансом, вычисляемая уверенность, обучение надёжности источников. У него уже есть команда tick под расписание.
  • Арбитр агента — приёмка. Harness, который выносит вердикт из реальных прогонов (коды возврата + захваченный вывод), а не из слов агента, что «должно работать».
  • Руки — codegen. Cursor или сам агент OpenClaw пишет минимальное изменение под текущую ступень.
  • Собачка — человек. Обязательная остановка и проверка полезности между каждой парой ступеней.

§3 Цикл одного сердцебиения

Один «удар» делает максимум одну попытку одной ступени и останавливается. Никакого цикла по ступеням внутри одного запуска.

  1. Прочитать лестницу, взять первую ступень со статусом не «отгружено».
  2. Если ступень ещё не одобрена человеком к старту — ничего не менять, показать «жду одобрения» и выйти.
  3. Сгенерировать минимальное изменение кода под намерение ступени.
  4. Прогнать приёмку ступени: команды как настоящие подпроцессы, захватить stdout, stderr и коды возврата.
  5. Зелено → git commit с привязкой к ступени, дописать журнал, пометить пройденной, остановиться и показать человеку. Не переходить к следующей ступени самостоятельно.
  6. Красно → git откат к последнему хорошему коммиту, дописать причину в журнал, показать человеку. Репозиторий никогда не остаётся сломанным.

§4 Лестница возможностей

Лестницу задаёт и редактирует только человек. Храповик читает её и обновляет лишь статус ступени — он не меняет порядок, не добавляет и не переписывает ступени. Каждая ступень — это намерение плюс приёмка (набор команд, которые должны вернуть ноль).

  "checks": [
    "python3 svod.py ingest sample_feed.txt",
    "python3 svod.py tick"
  ],
  "approved": false,
  "status": "pending"
}

§5 Гарантии

Это жёсткие правила, зашитые в код и конфиг, а не пожелания.

Песочница

Храповик работает только внутри каталога проекта и не выходит за его пределы; сеть — по белому списку или выключена. У OpenClaw есть доступ к шеллу и файлам, и его автономность уже срывалась с поводка (известен случай, когда агент сам завёл профиль на платформе знакомств без ведома владельца). Без присмотра он не должен мочь трогать ничего за пределами проекта.

Версионный контроль

Перед любым изменением рабочее дерево должно быть чистым (иначе сначала снапшот-коммит). Любое изменение либо коммитится, либо откатывается. Репозиторий никогда не остаётся в сломанном состоянии.

Ограниченность

Цели «довести до канона» не существует — есть только конечная лестница. Продвижение строго по одной ступени и только после человека. В коде не должно быть ни одной ветви, перебирающей ступени автономно.

Никакого самозачёта

Вердикт по ступени выводится исключительно из захваченного вывода приёмки (коды возврата). Мнение агента, что «должно работать», вердиктом не является. Это та же первая заповедь, что и у самого СВОДа: одинокому источнику, ставящему зачёт себе, верить нельзя.

§6 Журнал сборки

Append-only журнал фиксирует каждую попытку: время, id ступени, git sha (или «откат»), вердикт и захваченный вывод тестов. По сути это СВОД о собственной разработке: каждая запись — утверждение «ступень работает» с провенансом (конкретный прогон) и вердиктом. Главное свойство — воспроизводимость: повторный прогон приёмки ступени обязан совпадать с тем, что записано в журнале. Если не совпадает — есть скрытое состояние, и его надо вычистить.

§7 Промпт для Cursor

Промпт ниже строит сам храповик — оркестратор, приёмку и бегунок по лестнице, — а не ядро СВОДа: оно собирается отдельным промптом и предполагается уже существующим в репозитории. Вставить в Cursor целиком.

промпт для Cursor · построить храповик · можно копировать

Роль. Ты — инженер. Построй «храповик» — ограниченный цикл сборки, который растит проект СВОД по одной возможности за раз, с неподделываемой приёмкой и обязательной остановкой на человека между ступенями. Сразу создавай файлы и запускай; не берись за следующую задачу, пока приёмка текущей не зелёная. Контекст. Ядро СВОД (svod.py: утверждения с провенансом, вычисляемая уверенность, обучение надёжности источников, команды seed/add/ingest/ask/learn/sources/top/history/tick) уже есть в этом репозитории. Если его нет — остановись и сообщи, не пересобирай его наугад. Стек. Python 3.10+, только стандартная библиотека (subprocess, json, argparse, datetime, pathlib). git обязателен и вызывается через subprocess. Лестница — простой JSON-файл. Никаких внешних зависимостей. Всё рассчитано на запуск по сердцебиению OpenClaw: один удар = одна команда ratchet tick. Лестница (ladder.json). Упорядоченный список ступеней. Каждая: id, title, intent (какую возможность добавляем), checks (список команд оболочки — это и есть приёмка ступени), approved (bool, человек разрешил старт), status (pending | passed | shipped). Этот файл редактирует ТОЛЬКО человек. Храповик читает его и меняет лишь поле status; порядок и содержание не трогает. Приёмка (Арбитр). Для ступени выполни каждую команду из checks как настоящий подпроцесс. Захвати stdout, stderr и код возврата. Вердикт «зелено» — только если ВСЕ команды вернули 0. Вердикт выводится исключительно из кодов возврата и захваченного вывода, никогда из твоего мнения. Сырой вывод сохраняется в журнал как провенанс. Команда ratchet tick (один удар). Ровно один раз за вызов: 1) Прочитать ladder.json, найти первую ступень со status != shipped. 2) Если её approved = false — ничего не менять, напечатать «жду одобрения ступени X» и выйти с кодом 0. 3) Иначе внести минимальное изменение, реализующее intent ступени. 4) Прогнать приёмку ступени. 5) Зелено: git add+commit с сообщением «ratchet: passed», дописать журнал, выставить status = passed, напечатать сводку и ОСТАНОВИТЬСЯ. Не начинать следующую ступень. 6) Красно: git reset --hard к последнему коммиту (репозиторий обязан остаться рабочим), дописать в журнал причину и захваченный вывод, напечатать сводку и остановиться. За один tick — максимум одна попытка одной ступени. Никакого цикла по ступеням внутри вызова. Переход между ступенями. Храповик НИКОГДА не переводит passed → shipped и не берёт следующую ступень сам. Это делает человек: командой ratchet ship (помечает shipped) и/или выставляя approved=true у следующей. Не должно быть ни одного пути кода, который продвигается по лестнице без человека. Журнал (journal.jsonl, append-only). На каждую попытку: время, id ступени, git sha (или «откат»), вердикт, захваченный вывод тестов. Это «СВОД о собственной разработке»: запись = утверждение «ступень работает» с провенансом (прогон) и вердиктом. Повторный прогон приёмки обязан совпадать с журналом. Гарантии (зашей как жёсткие правила). — Песочница: работа только внутри каталога проекта; за его пределы не выходить; сеть по белому списку или выключена. — Версионный контроль: перед изменением дерево чистое (иначе снапшот-коммит); любое изменение либо коммитится, либо откатывается; репозиторий никогда не сломан. — Ограниченность: цели «довести до канона» НЕ существует, есть только конечная лестница; продвижение по одной ступени и только после человека. — Никакого самозачёта: вердикт только из захваченного вывода приёмки. Связка с OpenClaw (опиши в README, без кода конфигурации). ratchet tick ставится на сердцебиение/cron OpenClaw — один удар = один tick. Сводку, которую печатает tick, OpenClaw доставляет человеку в чат; человек отвечает одобрением следующей ступени, командой ship или запросом отката. Приёмка самого храповика (проверь себя и приложи вывод). — Дай ladder.json из 3 игрушечных ступеней; первая approved=true, остальные false. Один ratchet tick пытается ТОЛЬКО первую, прогоняет её реальные тесты и при зелёном — коммитит, помечает passed и останавливается, не трогая вторую. — На заведомо падающей ступени tick откатывает дерево к последнему коммиту и оставляет репозиторий рабочим (тесты ранее пройденного всё ещё зелёные). — Вердикт любой ступени воспроизводится повторным прогоном её checks и совпадает с журналом. — Без записанного одобрения/ship храповик отказывается продвигаться дальше. — В коде нет ветви, перебирающей ступени без человеческого шлюза. Запусти этот сценарий и приложи вывод как доказательство, что приёмка пройдена.

Признаки, что храповик исправен

  • За один удар сердцебиения трогается не больше одной ступени.
  • Любой вердикт воспроизводится повторным прогоном приёмки и совпадает с журналом.
  • После красной попытки репозиторий рабочий, ранее пройденное — зелёное.
  • Без явного одобрения человека лестница не двигается.
